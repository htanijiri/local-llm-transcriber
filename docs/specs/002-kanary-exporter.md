# 002 Kanary録音エクスポーター

- 状態：ドラフト
- 依存：001（2チャンネル入力フォーマット）

## 背景・課題
- Web会議の録音に Kanary（macOS の録音アプリ）を使うと、マイクとスピーカーを別チャンネルで録れる。
- 録音は各 Mac の Kanary 内に保存されるため、文字起こし用フォルダ（Google Drive）へ手で書き出す必要がある。
- 録音する Mac は、文字起こしを動かす Mac に限らない（例：外出先の MacBook）。

## ゴール
- Kanary の録音が終わったら、自動で 001 の2チャンネル入力フォーマットで Drive の監視フォルダに書き出す。
- 文字起こし本体（mlx-whisper 等）を入れていない Mac でも、少ない準備で動かせる。

## やらないこと
- 文字起こし・要約（001 と既存パイプラインが担当）。
- Kanary 側の録音の削除（書き出した後も Kanary に残す）。
- Kanary のアプリデータのディレクトリを直接読むこと。公式の `kanary` CLI だけを使う。
- Drive へのアップロード処理（Drive for desktop のマウントフォルダに書くだけ）。

## 受け入れ条件
- [ ] AC1：`kanary-export` を1回実行すると、未書き出しで録音が完了している録音を、すべて `<出力先>/<名前>.2ch/` に `mic.m4a`、`speaker.m4a`、`manifest.json` として書き出す。
- [ ] AC2：一度書き出した録音は、次回以降に再度書き出さない（書き出し済みの記録を Mac ごとに持つ）。
- [ ] AC3：録音中の録音は書き出さない。
- [ ] AC4：`manifest.json` は2つの音声ファイルを書き終えた後に書き、各ファイルのバイト数を含む。書き出しはいったん一時フォルダに行い、完成してから出力先に移す（途中の状態を watch に見せない）。
- [ ] AC5：`kanary` CLI が使えない、Kanary.app が起動していない、出力先（Drive）がマウントされていない場合は、何も書き出さずにエラーを記録して終了する（出力先のフォルダを勝手に作らない）。
- [ ] AC6：Python 標準ライブラリだけで動き、文字起こし本体の依存（mlx-whisper、torch 等）をインストールせずに使える。
- [ ] AC7：launchd で定期実行する設定（plist の雛形とインストール手順）があり、別の Mac でも README の手順だけで導入できる。
- [ ] AC8：複数の Mac から同じ出力先に書き出しても、フォルダ名が衝突しない。

## 設計方針
- `kanary recordings list` で一覧を取り、状態が録音完了（例：`recorded`／`transcribed`）のものを対象にする。
- `kanary recordings export <id> <path> --channel mic` と `--channel speaker` で2ファイルを書き出す。
- フォルダ名：`<録音開始日時 YYYYMMDD-HHMM>_<タイトル>_<id の末尾数文字>.2ch`。ファイル名に使えない文字は置き換える。id の末尾で Mac 間の衝突を避ける（AC8）。
- 書き出し済みの記録：`~/Library/Application Support/kanary-exporter/exported.json`（Mac ごと）。Drive 上には置かない。
- 設定：出力先のパスと実行間隔。`~/.config/kanary-exporter/config.toml` または環境変数。
- 配置：このリポジトリ内の独立したディレクトリ（例：`tools/kanary_exporter/`）に、依存なしの別パッケージとして置く。`uv tool install` でインストールできるようにする。
- 定期実行：launchd の `StartInterval`（例：5分）。常駐ループにはしない。

## 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 既存の `lt` にサブコマンドとして追加 | × | 他の Mac で mlx-whisper・torch まで入ることになり重い |
| 依存なしの独立ツール | ○ | `kanary` と Python があれば動く |
| Kanary のデータディレクトリを直接監視 | × | 非公開の内部構造に依存し、壊れやすい。CLI が公式の手段 |
| 常駐して録音終了を検知 | × | 定期実行で十分。launchd の定期起動の方が落ちたときも安全 |

## 検証方法
- 自動テスト：`kanary` CLI の JSON 出力をダミーにして、対象の選別（録音中の除外・書き出し済みの除外）、フォルダ名の生成、マニフェストの内容、エラー時に何も書かないことを確認（AC1〜5, 8）。
- 手動確認：実際の Kanary で短いテスト録音を作り、書き出し→Drive 同期→mac mini の watch で 001 の処理まで通す。
- 別の Mac（MacBook）で、README の手順だけで導入できることを確認（AC6, 7）。

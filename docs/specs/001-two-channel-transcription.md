# 001 2チャンネル音声の話者ラベル付き文字起こし

- 状態：ドラフト
- 依存：000（検証の土台）

## 背景・課題
- Web会議を録音アプリ（例：Kanary）で録ると、マイク（自分）とスピーカー（相手）の音声を別々のファイルとして取り出せる。
- 今のパイプラインは音声を1本として文字起こしするため、誰の発言かがわからない。
  2本に分かれていれば、話者分離モデルを使わなくても「自分／相手」を確実に区別できる。
- 今の watch は音声ファイルを1つずつ独立に処理するので、マイクとスピーカーの2ファイルを置くと別々の会議として2回処理されてしまう。

## ゴール
- マイク音声とスピーカー音声の組を1つの会議として扱い、発言を時刻順に並べ、話者ラベル（自分／相手）付きの文字起こしを作る。
- その文字起こしから、今までどおり議事録を作る。
- 手動（`lt` コマンド）でも、watch による自動処理でも使える。

## やらないこと
- スピーカー側に含まれる複数の相手を、人ごとに分離すること（全員「相手」とする）。
- マイクへのスピーカー音の回り込み（エコー）対策。ヘッドセットの使用を前提とする。
- 1チャンネルの音声に対する話者分離（diarization）。
- 特定の録音アプリへの依存。入力は下記の「2チャンネル入力フォーマット」に従っていればよく、Kanary 固有の処理は 002 に閉じ込める。

## 受け入れ条件
- [ ] AC1：`lt run <組のフォルダ>` で、話者ラベル付きの文字起こし `transcript_dir/<名前>.txt` と議事録 `summary_dir/<名前>.md` ができる。
- [ ] AC2：文字起こしは発言の開始時刻順に並び、各行が `[HH:MM:SS] 自分: …` または `[HH:MM:SS] 相手: …` の形式になっている。
- [ ] AC3：時刻は2つのチャンネルで同じ基準（録音開始からの経過時間）になっている。先頭無音トリムでチャンネルごとに時刻がずれない。
- [ ] AC4：watch は組のフォルダを1件として扱い、2ファイル分を別々に処理しない。
- [ ] AC5：watch は組がそろうまで処理しない。マニフェストに書かれたファイルがすべて存在し、サイズが一致し、安定してから処理する（Drive の同期順は保証されないため）。
- [ ] AC6：片方のチャンネルがほぼ無音でも、そのチャンネルの幻聴（「ご視聴ありがとうございました」等）が文字起こしに混ざらない。
- [ ] AC7：今までの1ファイル入力の動作（出力形式を含む）は変わらない。
- [ ] AC8：議事録で、「自分」と「相手」の発言が区別されて扱われる（例：決定事項や担当者の主語が崩れない）。

## 設計方針
### 2チャンネル入力フォーマット（002 との取り決め）
```
<watch_dir>/
  20260917-1030_週次定例.2ch/      ← 拡張子 .2ch のフォルダが1件の会議
    manifest.json                   ← 最後に書く
    mic.m4a                         ← 自分
    speaker.m4a                     ← 相手
```
```json
{
  "format": "2ch-v1",
  "title": "週次定例",
  "recorded_at": "2026-09-17T10:30:00+09:00",
  "channels": {
    "mic":     { "file": "mic.m4a",     "label": "自分", "bytes": 1234567 },
    "speaker": { "file": "speaker.m4a", "label": "相手", "bytes": 2345678 }
  },
  "source": { "app": "kanary", "id": "..." }
}
```
- 出力ファイル名はフォルダ名から `.2ch` を除いたもの（例：`20260917-1030_週次定例.txt`）。Web などの既存の一覧はそのまま使える。
- ラベルはマニフェストの `label` を使い、コードに「自分／相手」を直書きしない。

### 処理
- チャンネルごとに mlx-whisper で文字起こしし、`result["segments"]` の開始・終了時刻を使って1本のタイムラインにまとめる。
- 先頭無音トリムは時刻の基準を壊すので、2チャンネル入力では使わない。代わりに、無音区間の幻聴は `no_speech_threshold`、`hallucination_silence_threshold` などで抑える（AC6 は実験で決める）。
- 要約プロンプトに話者ラベルの意味を伝える（`prompts/` に追記、または2チャンネル用のプロンプトを追加）。
- watch：`*.2ch` フォルダも走査対象にし、完了判定（`summary_dir/<名前>.md` の有無）と再試行の仕組みは既存と共通にする。

## 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 2ファイルを並べて置き、ファイル名の規則（`xxx.mic.m4a` 等）で組にする | × | Drive の同期順が不定で、片方だけ届いた状態を判定しにくい |
| フォルダ＋マニフェスト | ○ | 組の境界が明確で、サイズで到着完了を判定できる |
| 2チャンネルを混ぜて1本にし、話者分離モデル（pyannote 等）を使う | × | 分離済みの情報を捨てることになり、精度も下がる。依存も重い |

## 検証方法
- 自動テスト：セグメントのマージと整形（時刻順・ラベル・時刻フォーマット）、マニフェストの検証（欠落・サイズ不一致・未安定）、watch が組を1件として扱うこと（AC2, 4, 5, 7）。Whisper はダミー。
- スモークテスト：`say` で「自分」と「相手」のセリフを別々に生成し、無音を挟んで時刻をずらした2ファイルで組を作り、`lt run` を通す（AC1, 3）。
- 手動確認：実際の Web 会議の録音で、幻聴の有無と議事録の話者の扱いを確認する（AC6, 8）。結果は TECH_NOTES に残す。

## 未決事項

- 片方のチャンネルが完全に空、または欠けている場合に、エラーにするか1チャンネルとして処理するか。
